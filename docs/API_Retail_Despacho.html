API de costo de despacho Retail

DOCUMENTO DE INTEGRACIÓN / OCTUBRE 2026 / CRITERIO retail-2026-10 / VERSIÓN 3
SAP consulta esta API al momento de la orden y usa el costo que responde. La cartonización, la vía y el tarifario ya están resueltos. No hace falta reimplementarlos en SAP.

01Qué calcula

El costo de despacho de una orden Retail, en pesos, según el tarifario de lista vigente. El peso que se cotiza es el volumen externo de cada caja dividido por 4.000. El peso físico del maestro no se usa.

La orden se parte en facturas. Mezz (veterinaria, cosmético y nutrición) es una. Refrigerado es otra. Farma es otra. Controlado ambiente es otra. Controlado refrigerado es otra. Cada factura se cotiza sola y el costo de la orden es la suma.

Hoy la API no pide usuario ni token. El acceso queda limitado por la red. Para habilitar la llamada desde SAP se necesita la IP interna del servidor que la va a ejecutar, y el puerto se abre solo hacia esa dirección.

Tiempo de respuesta y timeout

  • Tiempo de respuesta medido: entre 0,2 y 0,4 segundos por orden.
  • Timeout recomendado en SAP: 10 segundos.
  • Si la API no responde dentro del timeout, SAP no debe bloquear la orden de venta: la graba sin costo de despacho y la deja marcada para cotizar después.
  • No reintentar en bucle. Basta con un reintento, o volver a cotizar cuando se modifique la orden.

03Entrada

Tres datos: cliente, SKU y cantidad. La comuna, la región, la ruta y el courier no se envían: salen de la ficha del cliente en SAP.

04Reglas que aplica la API

Canal

Solo clientes cuya estratificación es Retail. Un Cenabast, una clínica u otro canal se rechaza. La API no calcula esos canales.

Tarifario

La ruta por defecto de la dirección de despacho del cliente elige el courier.

  • COURIER-N usa el tarifario de Newtrans.
  • COURIER-T usa el tarifario de Transfarma.
  • Una ruta propia, como RUTA-C1 o RUTA-A1, no se cotiza. Esa ficha todavía no tiene courier.

Tarifario de respaldo

Si el courier del cliente no tiene tramo para la comuna y vía de una factura, la API cotiza esa factura con el tarifario del otro courier: Transfarma como respaldo de Newtrans, y Newtrans como respaldo de Transfarma. El objetivo es cobrar un costo de referencia antes que no cobrar.
  • El respaldo se decide factura por factura. En una misma orden, una factura puede usar el tarifario propio y otra el de respaldo.
  • Cada factura informa en courier el tarifario que se usó y en respaldo si fue el de respaldo.
  • Cuando se usa el respaldo, avisos trae una línea que lo explica.
  • Solo se usan Newtrans y Transfarma. Otros couriers no se consideran como respaldo.
  • Si ninguno de los dos tiene tramo, la factura queda sin costo (ver sección 05).

Comuna

La comuna de despacho de la ficha del cliente se busca en el tarifario tal como viene de SAP. Si no se encuentra, se busca su nombre corregido según la tabla de equivalencias TRP.Matriz_Comuna_Correccion (por ejemplo, TIL TIL corresponde a Tiltil y PUERTO NATALES a Natales). Para agregar una equivalencia nueva basta con una fila en esa tabla.

Vía

  • Aérea. Todo lo que va a Isla de Pascua, cualquier tipo de producto.
  • Aérea. La factura es refrigerada y el destino es Arica y Parinacota, Tarapacá, Antofagasta, Aysén o Magallanes. El controlado refrigerado entra aquí.
  • Terrestre. Todo lo demás: lo ambiente en cualquier región, y lo refrigerado que no va a esas cinco regiones.

Si una orden mezcla facturas de distinta vía, el campo via de la respuesta queda en Mixta. Cada factura trae la suya.

05Salida

SAP usa costo siempre que venga con valor, aunque sea parcial. Es preferible cobrar un costo parcial a no cobrar.
  • costo_completo: true: todas las facturas se cotizaron, con el tarifario propio o con el de respaldo.
  • costo_completo: false: alguna factura no encontró tramo ni en Newtrans ni en Transfarma. costo trae la suma de las que sí cotizaron y el motivo viene en facturas[].motivo.
  • Si un SKU no existe en el maestro o no tiene medidas, no se cotiza y se informa en avisos. El resto de la orden se cotiza igual.
  • Si costo viene nulo (ninguna factura cotizó), no se graba costo.

Cuando costo_completo es false o avisos no viene vacío, el costo es parcial o de respaldo. Se sugiere dejar la orden marcada para revisión.

08Qué no hace

  • No graba nada en SAP. Quien llama decide dónde dejar el costo en la orden.
  • No calcula canales distintos de Retail.
  • No cotiza clientes cuya ruta no es Courier N ni Courier T.
  • No usa el peso físico del producto.
  • No elige el courier más barato. Usa el tarifario de la ruta del cliente y el del otro courier solo como respaldo cuando el propio no tiene tramo.
